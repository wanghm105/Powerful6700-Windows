# FL2 / FL3 移植到 A6700：现状与结论

更新时间：2026-10-24　相机：ILCE-6700 / 固件 2.00　方式：静态反汇编 + 只读 dump + RAM 探测

参考实现：`refs/a7c2-fl23`（A7C2 / 固件 2.01 的 FL2·FL3 工具）。本文偏移都属于
`firmware/appFw-2.00.so`（89,027,992 B）与 `firmware/cp/cpapp-b.bin`（17,892,024 B）。

## 0. 一句话结论

- **颜色层可达**：CP 单元（0x02a40001 / 0x02a4000d）的读写在真机上已跑通，改完立刻可见，掉电恢复。
- **但只改色度 / 矩阵 ≈ 相机内的「饱和度」滑块**，用户当场判定「我在相机里面也能改」，产品价值不足。
- **真正的 FL2/FL3 需要 A7C2 那套四层移植**；A6700 上还缺三处定位（appFw 外观定义与菜单门、cpapp 参数槽与 gamma 表）。
- **「菜单里出现 FL2/FL3 字样」目前无解**：A7C2 固件出厂自带这两个标签，A6700 固件里 `FL2`/`FL3` 全 0 命中，
  显示文字在压缩 / 加密的 UI 资源里，不解开就无法新增或改名。

## 1. 静态定位（已确认）

### 1.1 appFw：外观编号 → CP mode 转换器

- 函数序言 `0x34e54ac`，转换核心 `0x34e5604`（A7C2 对应 `0x3528804`，结构同构）。
- 代码：`cmp w1,#9` → `b.hi 0x34e5674`（打「非法外观」日志）→ `adrp x0,0x40b6000` + `add x0,x0,#0x24`
  → `ldrb w0,[x0,w1,uxtw]` → `adr x1,0x34e5624` + `add x0,x1,w0,sxtb #2` → `br x0`。
- 索引表 `0x40b6024`（10 项 ×4）：`12 00 02 04 06 08 0a 0c 0e 10`；`0x12` 指向默认块 `0x34e566c`
  （`strb wzr,[x2]; ret`）。
- 映射：**0→0、1→3、2→2、3→1、4→0x10、5→0x0f、6→0x11、7→0x12、8→5、9→0x0d**。
- A7C2 打过补丁的表是 `00 03 02 01 10 0f 11 12 05 0d 13 14`：**前 10 项与 A6700 逐项相同**，
  A7C2 只是把上限 9→11 并追加 mode 0x13 / 0x14。
- 该函数既没有 `bl` 调用者，也没有 rela addend / u64 指针指向它 → 只能被间接派发（别再用 bl 扫描找调用者）。

### 1.2 CP（cpapp-b.bin）：单元目录与初始化数据块

- 单元目录 `0xc2a5b0`，19 条 12 字节 `{u32 key, u32 RAM 地址, u32 size}`：
  `0x02a40000 → 0x016efe94 / 0x1200`、`0x02a40001 → 0x016f1094 / 0x2000`、
  `0x02a40009 → 0x016f3094 / 0x400`、`0x02a4000b → 0x016f3494 / 0x100`、
  `0x02a4000d → 0x016f3594 / 0x7000`、`0x02a4000e → 0x016fa594 / 0x700`，另有两组 `0x019e…` / `0x01a1…`。
  8192 / 28672 与 A7C2 的单元尺寸完全一致 → 两机 CP 单元体系同源。
- 同一个目录在 `nflasha8-2.00.bin` 的 `0xe765b0`（cpapp-b.bin 在分区里从 `0x24C000` 开始）。
- 初始化数据长度字段在 `cpapp 0x20140`，本机值 `0x001412B8`（全文件唯一），推得数据块
  **[0xFBF000, 0x11002B8)**，其后还有 0x10000 字节全零尾块可作追加空间。
- 两个颜色单元在镜像里**全 0**（不论 Δ 取 0x5EA9DC / 0x5FA9DC）→ 颜色 / 矩阵是 CP 启动后填充的 BSS，
  静态镜像里没有可复制的字节 → 只能走运行时 `cp_read` / `cp_write`。

### 1.3 CP：32 路「外观类别 → 参数」填表函数

- `0x135b30`：`push {r4,r6,r7,lr}` → `ldrd r3,lr,[r0]` → `ldrb.w r2,[r3,#0x2e]`（键）→ `subs r0,r2,#1`
  → `cmp r0,#0x1f` → `bhi 0x135c54` → `ldrb.w ip,[r3,#0x17]` → `tbh [pc,r0,lsl#1]`，跳表基址 `0x135b4c`。
- 键 15/16/17/18（CP mode 0x0f/0x10/0x11/0x12）→ 参数 `0x2d`/`0x2e`/`0x2f`/`0x30`（45..48）。
- 键 19/20（mode 0x13/0x14）→ 处理块 `0x135c9e` / `0x135cb0`（`movs r0,#4` / `#5` + `strb r0,[r1,#2]`，
  随后 `movw r0,#0x1094; movt r0,#0x16f` 读单元 0x02a40001）→ **这两个 mode 的调度入口在 A6700 CP 里已存在**。
- 调用者只有两处：`0x135084`、`0x1350e6`，都在 `0x1350xx` 的外观参数解析函数内。

## 2. 运行时 CP 单元（真机读数，工具 `tools/cp_read.py`）

| 单元 | 字节 | 非零字节 | sha256 |
| --- | ---: | ---: | --- |
| 0x02a40001 | 8,192 | 2,815 | 91d5e04018cacae6afa1e16c19157ebcd72c7833a5de0d0c220bc963c22c066c |
| 0x02a4000d | 28,672 | 8,752 | 64ceb9aa0279493eff598cc37e024b51e1573f678f73bdaf2c878f6147d9b209 |

落盘：`firmware/cp/unit-02a40001.bin`、`firmware/cp/unit-02a4000d.bin`。

布局（与 A7C2 模型一致）：

- 单元 0x02a40001：参数表 `0x1200`（1 B/参数）；chroma 记录 `0x1250 + 槽×64`，每条 32 int16 =
  **24 个有效 + 尾 8 个 0**（对应 donor 的 `cc1_int16` 3×8 形状）。可用槽数 `(8192-0x1250)/64 = 54`，
  末尾 48 字节不可用；实际非零的色度槽：**0..21、28、29、32..39**。
- 单元 0x02a4000d：参数表 `0x196`；矩阵记录 `0x1e0 + 槽×768`（前 576 B = 3 端点 × 16 × 6 int16）。
  实际在用的矩阵槽：**0..19、32、33**，20..31 全零。

参数表前 52 字节（unit01 @0x1200）：

```
00 02 04 00 00 00 06 02 00 00 01 00 20 11 12 22 22 22 13 25 21 01
03 05 00 00 00 07 03 00 00 26 20 11 12 23 23 23 13 25 10 08 0e 0a
0c 09 0f 0b 0d 13
```

- 索引 45..48 = `09 0f 0b 0d`，正好对上「mode 0x0f..0x12 → 参数 45..48」。
- 两个单元在索引 41..48 上完全相同：`41..48 = 8,14,10,12,9,15,11,13`；索引 23 = 5（VV2）、41 = 8（FL）、45 = 9（SE）。
- 因此参数值是**整族编号**、两个单元共用，不能直接当作「各自单元的槽号」。

> 语义提示：`cp_write` 后 `cp_read` 立刻一致，说明这两块是**活的 RAM**；发 `STOP_SENSER`、拔插 USB 后
> 内容仍保留，只有真正掉电（关机 / 取电池）才回原厂。所有 RAM 探测因此可以连续做，不必每次重写。

## 3. 真机探测：槽号归属（路线 C 的成果与边界）

工具：`tools/cp_write.py`（单单元、`--keep-service`）、`tools/cp_patch.py`（一次会话连写多个单元，
自动留 `.orig`、回读比对）。所有探测只改 RAM，掉电恢复。

| 探测文件 | 改动 | 机身观察 |
| --- | --- | --- |
| `unit-02a40001.chroma_zero.bin` | 全部 32 个色度槽清零 | 所有外观都变灰（CP 色度表是活的） |
| `unit-02a40001.zero9.bin` | 只清零槽 9 | **SE 变灰** |
| `unit-02a40001.zero11.bin` | 只清零槽 11 | 看不出变化 |
| `unit-02a40001.zero5.bin` | 只清零槽 5 | **VV2 变灰** |
| `unit-02a40001.tri_678.bin` | 槽 6 ×4 / 槽 7 取反 / 槽 8 清零 | **PT 变艳、FL 与 2FL 一起变黑白** |
| `unit-02a40001.fl2_at_slot8.bin` + `unit-02a4000d.fl2_at_slot8.bin` | 把 FX2 donor 的 FL2 写进槽 8（色度 + 矩阵） | 肉眼无差别（拍 FL 对比确认） |
| `unit-02a4000d.zero_matrix8.bin` | 矩阵槽 8 全 0 | 只有饱和度变化，颜色没塌 |

实测槽位归属：**槽 5 = VV2、槽 6 = PT、槽 8 = FL（2FL 与它绑在同一组参数上）、槽 9 = SE**。
用户给出的相机菜单顺序（16 项）：`ST, PT, NT, VV, VV2, FL, IN, SH, BW, SE, 1ST, 2FL, 3IN, 4SH, 5VV2, 6BW`。

**边界**：把 FL 槽换成 FX2 的 FL2 donor 数据后没有可见差异；矩阵槽归零也只是饱和度变化。
用户结论：这一层能做的等价于相机内可调项（对比度 / 高光 / 阴影 / 褪色 / 饱和度 / 锐度 / 锐度范围 / 清晰）。

## 4. WBI 与菜单模型

### 4.1 nflasha5（WBI）里的外观相关 blob 名

- `CREATIVE_STYLE_PLUS_{STANDARD,VIVID,NEUTRAL,PORTRAIT,FILM,SEPIA,RETRO,AIRY,BRILLIANT,BLACK_WHITE,INVALID}`
- `CREATIVE_STYLE_PLUS_CREATIVE_BOX_1..6` ← 菜单里的 `1ST / 2FL / 3IN / 4SH / 5VV2 / 6BW` 六个**可编辑自定义位**
- `ICON_TOUCH_FUNCTION_AUTO_CUSTOMIZE_CREATIVE_LOOK_*`、`CINEMATIC_MODE_LOOK_*`（含 USER1..USER16）

### 4.2 菜单缩写 ↔ 固件枚举

appFw 名字表（`0x36531c8` 起）顺序：`AUTO / STANDARD / PORTRAIT / NEUTRAL / VIVID / BRILLIANT / FILM /
RETRO / AIRY / BLACK_WHITE / SEPIA`，对应菜单 `ST / PT / NT / VV / VV2(=BRILLIANT) / FL(=FILM) /
IN(=RETRO) / SH(=AIRY) / BW / SE(=SEPIA)`。

cpapp-b.bin 里还有两张旧式名字表（`0x146950`、`0x1475dc`）：`SH IN VV2 FL Sepia Autumnleaves Nightview
Sunset Light Deep Clear BW Landscape Portrait Neutral Vivid Off Standard`（老机型 Creative Style 的遗留串）。

### 4.3 标签不可得（硬证据）

- `FL2` / `FL3` 在 appFw、cpapp、nflasha8、nflasha5 里 **全部 0 命中**。
- UTF-16LE 的 `VV2` / `Standard` / `Sepia` 在 appFw 与 WBI 里也 **0 命中**。
- appFw 里 zlib 流扫描：3,756 个候选位置，解压成功 **0** 个。
- A7C2 的 `patches.json` 里 8 处 appFw 写入全是开关位 / 映射表 / 槽位绑定，**没有一处写文本**
  → A7C2 能显示 FL2/FL3 是因为它固件出厂就带这两个标签，工具只是把开关打开。
- 结论：A6700 上要新增或改名菜单项，必须先解开 Sony 的 UI 文本资源容器（bci BlobWrapper 一类）。

## 5. 自定义外观设置的落盘位置（两轮全分区 diff，未定位）

做法：用户在相机里把 `2FL` 八个参数全部拉到 9 → dump 全部分区（ext 态）；再调回默认、关机重开 →
再 dump 一遍（def 态）；逐分区对比。

| 分区 | 差异 | 性质 |
| --- | ---: | --- |
| nflasha5（WBI） | 0 B | sha256 前后完全一致 `56e0e220…` |
| nflasha8（CP） | 0 B | sha256 前后完全一致 `3bddcce3…` |
| nflasha10 | 534 B | 指针表 / 运行痕迹 |
| nflasha2 | 4,161 B | UPDATER 区重写 |
| nflasha6 | 变化 | JIT 缓存 |
| nflasha11 | 38 B | 计数器 |
| nflasha15 | 未全量 dump | 头部 cramfs + gzip，是固件镜像 |

结论：**没有找到任何 look 参数记录**；参数落盘位置仍未定位（可能在加密资源区内）。
因此「把 FX2 数据注入自定义位」这条路暂时没有落点。

## 6. A7C2 的四层做法 vs A6700 缺口

| 层 | A7C2 做了什么 | A6700 现状 |
| --- | --- | --- |
| ① appFw 开门 | 上限 9→11、12 字节表追加 0x13/0x14、两个选择能力位（0x4b2ed19）、FL2/FL3 出厂 Fade 默认（0x4b3b544 / 0x4b3b54c）、槽 16/17 绑定（0x4b4a5e4 / 0x4b4a5ec）、两个菜单产品标志（0x59892ca / 0x5989382） | 转换器已定位；**外观定义表 / 菜单门 / 槽位绑定表未定位** |
| ② cpapp 扩容 | 数据长度 0x141b80→0x142aa0（+3872 B）、在 0x1100b80 追加 curve / gamma / mode 表、gamma 上界 0x2f→0x32、三处表指针改到新地址（指针差推得 RAM = 文件偏移 + 0x108900） | 长度字段与追加空间位置已确认；**参数 55/56 槽、gamma 表、chroma / 矩阵白名单未定位** |
| ③ 运行时写槽 | `cp_read` / `cp_write` 把 FL2/FL3 的 chroma(64 B) / 矩阵(576 B) 写到参数 55/56、槽 23/25 | **已打通**（0x603/0x40 读、0x603/0x41 写），但目标槽号在 A6700 是 5/6/8/9 这一族，需重定 |
| ④ donor 数据 | 取自 FX2 固件的 `assets/fx2_fl23_donor.json`（cc1_int16 3×8、matrix 3×16×6 int16、gamma 记录） | 数据在手，可直接复用 |

## 7. 三条路线与现状判断

- **路线 A（完整移植，对齐 A7C2）**：产出是相机菜单里真的多出两个外观。阻塞点：① 新外观没有显示文字（§4.3）；
  ② appFw 外观定义 / 菜单门未定位；③ cpapp gamma 表未定位；④ 需要新写窗口（现有 260 扇区不覆盖），要重做 catalog 与结构守卫。
- **路线 B（只加两个「无名」外观）**：先改转换器上限与外观数量，第 11/12 项指向已有 mode，验证菜单能否多出两项。
  改动小、可回退，但显示名与颜色都不是新东西。
- **路线 C（改已有外观的颜色）**：已完成并验证到边界 —— 等价于相机内饱和度，价值不足。

## 8. 已经排除的思路（别重复）

- 用 `bl` 扫描找转换器调用者 → 0 命中；用 rela addend / u64 指针查引用 → 0 命中（间接派发）。
- 在 appFw 里搜 CP mode 字节序列（`10 0f 11 12`、`00 03 02 01 10 0f 11 12 05 0d`）→ 0 命中（模式号只在代码里）。
- 按文案 id / 属性 id 立即数反查判定点（卡速那条线）→ 判定端只传「档位索引」，原理上不可能命中。
- 在 WBI / appFw 里找明文外观名或 zlib 压缩文本 → 全部 0 命中。
- 猜「槽 11 = FL」（因为它的色度数值与 donor 的 FL2 接近）→ 归零后机身毫无变化。
- 直接把 donor 的 FL2 数据写进 FL 槽（槽 8）→ 肉眼无差别。
- 用全分区 diff 找自定义外观参数 → 两轮对比没有找到记录。

## 9. 下一步（两条并行，均有明确判据）

1. **UI 文本可行性探针（约 30–60 分钟，纯静态）**：定位 appFw 里「谁给菜单提供 look 名称」的代码路径。
   判据：若名字来自「查表 + id」就还有戏（可以加名字）；若指向加密资源包，就停止这条线。
2. **cpapp 侧静态定位**：找 A6700 的 gamma 表 / 模式表 / 参数 55-56 对应物（对齐 §6 第 ② 层的 A7C2 补丁点）。
   判据：能给出「参数表上界、gamma 表地址、chroma / 矩阵白名单」三处具体偏移，并能在 dry-run 中复现 A7C2 的 32 条写入。

两条都成立后，才谈新写窗口与真机写入；任一条不成立，FL2/FL3 在 A6700 上就只能停在「颜色近似」这一层。
