# CC / NC 外观落地（A6700 + 固件 2.00）

> **缩写说明**：早期研究阶段的内部代号写作 `CN` = Classic Negative；软件界面、README 与相机菜单统一写 `NC`。文件名（`docs/CC-CN*.md`、`tools/apply_cc_cn.py`）保留历史名，不改。

目标：让 A6700 的外观菜单里出现 **CC / NC** 两项，观感来自相机 SD 卡里的
`Fuji_CC.cube` / `Fuji_CN.cube`（已取回本机：`firmware/lut/Fuji_CC.cube` 1,020,400 B、
`firmware/lut/Fuji_CN.cube` 1,002,584 B，均为 LUT_3D_SIZE 33、无 DOMAIN、值域 0..1）。

## 1. 已确认的能力边界

| 层 | 载体 | 现状 |
| --- | --- | --- |
| 颜色（矩阵 + 色度） | CP 单元 `0x02a40001`（8,192 B）/ `0x02a4000d`（28,672 B），运行时可写 | ✅ 已打通，写后回读一致 |
| 持久化 | 正常关机时相机把 CP 单元写进 `/setting/BACKUP.BIN`（偏移表见 `docs/PERSIST-STORE.md`） | ✅ 已用标记实测 |
| 名称 | `/usr/share/app/string_simplifiedchinese_f.uxc`（短码 ST/PT/… 都在这里） | ✅ /usr 可写、断电保留 |
| 伽马/影调曲线 | cpapp 初始化数据块 9 × 1024 B 恒等曲线（`0xfe0b50` 起，步长 `0x400`） | ❌ 未验证是否按外观灌值 |

拟合精度实测（对 35,937 个采样点）：单组 3×3+偏移 RMSE 0.177，16 段分带 3×3 RMSE 0.156，
曲线层 + 16 段矩阵 RMSE 0.148 —— **CP 的「矩阵 + 色度」模型无法表达 Resolve 这类胶片 LUT 的 S 形影调**，
只能还原颜色倾向。要接近 A7C2 的观感必须补伽马层（那是 cpapp 初始化数据层，属改固件）。

## 2. 外观 ↔ CP 槽位账本（实机二分所得）

外观家族共享同一条色度/矩阵记录，因此「改一个 = 连带它的自定义位一起变」。

| 外观 | 菜单位次 | CP 槽 | 依据 |
| --- | --- | --- | --- |
| ST（含 1ST） | 1 | **0** | 零化槽 0 → ST 与 1ST 同时变黑白 |
| VV | 4 | **1 或 2** | 零化 {0,1,2} 时 VV 变、NT 不变；零化槽 0 时 VV 不变 |
| NT | 3 | **4** | 零化 {3,4} → NT 变；零化槽 3 → 无变化 |
| VV2（含 5VV2） | 5 | **5** | 零化槽 5 |
| PT | 2 | **6** | 槽 6 放大 → PT 变艳 |
| FL（含 2FL） | 6 | **8** | 零化槽 8 |
| SE | 10 | **9** | 零化槽 9 |
| IN（含 3IN）、SH（含 4SH） | 7、8 | 在 10–19 内 | 零化 10–19 → vv2/in/sh/3in/4sh/5vv2 变 |
| BW | 9 | **无独立色度记录** | 零化 20,21,28..39 与全部低槽均无变化 |
| 槽 3、20、21、28、29、32–39 | — | 对画面无可见影响 | 实验确认 |

## 3. 记录结构（待本轮验证）

- 色度：`unit01[0x1250 + slot*64]`，64 B（24 个有效 int16 + 尾部 8 个 0）
- 矩阵：`unit0d[0x1e0 + slot*768]`，768 B（每 6 个 int16 一组）
- 验证实验：把 **SE（槽 9）的色度与矩阵整块复制到 NT（槽 4）**。
  若 NT 观感与 SE 一致 ⇒ 槽位独立 + 记录结构正确，可直接写入合成数据。

## 4. 落地顺序

1. （进行中）验证记录结构：NT ← SE。
2. 用 `Fuji_CC.cube` / `Fuji_CN.cube` 拟合出槽 6（PT→CC）、槽 4（NT→NC）的矩阵 + 色度并写入。
3. 改短码：`PT → CC`、`NT → NC`（`string_simplifiedchinese_f.uxc`，同长度就地改）。
4. 正常关机 → 相机把 CP 单元固化进 `/setting/BACKUP.BIN`；重启验收。
5. 回滚：任一时刻可用 `firmware/cp/live/*.bin` 写回，或从 `firmware/setting/BACKUP-live.bin` 恢复。

## 7. 2026-10-24 突破：CC1 的真实语义与 A 版落地

### 7.1 结论（实测，已生效）

- **CC1（unit 0x02a40001，`0x1250 + slot*64`）的 8 个 int16 不是「1024 为单位阵基底的矩阵」**。
  那个 1024 公式只适用于 block13（unit 0x02a4000d），我一开始错用了。
- **全 0 = 完全去色**（实测：PT/NT 变近乎黑白，只余极淡色偏）。因此这 8 个数是
  「灰度基座 + 色度幅度」的编码：值越大彩色越浓，0 就是黑白。
- **按同一比例 alpha 缩放工厂系数 = 线性降低彩色浓度**，亮度与白点不变。
  实测 alpha=0.60（PT→CC）与 0.80（NT→NC）一次成立，蓝色不再溢出。
- 之前那次「50% 等权去饱和」导致蓝色溢出，不是模型问题，是我给的系数
  比例与符号都不对（e/f 写成负数），等于在灰度基座上乱加色。

### 7.2 关键实验链（按时间）

| 写入内容 | 结果 | 结论 |
| --- | --- | --- |
| 槽 6 = 通道轮换 a=-1024,d=-1024,e=-1024 | 只有 PT 变黑白 | 槽位映射成立，但置换不是饱和度旋钮 |
| 槽 6 = 等权去饱和（a..f ≈ -171） | 变淡但蓝色溢出 | 系数比例错，模型未证伪 |
| 槽 6 = 全 0（以为是单位阵） | 近乎黑白 | **推翻 1024 基底假设** |
| 槽 6 = 0.60×工厂、槽 4 = 0.80×工厂 | 浓度正确、亮度不变 | **线性缩放模型成立（当前方案）** |

照片对照法（有效，可复用）：相机固定机位与曝光，只切外观，同场景拍 ST/PT/NT 三张 JPEG，
再按像素统计比较饱和度与色相 —— 比肉眼描述可靠得多。

### 7.4 关于那两个 .cube

`Fuji_CC.cube` / `Fuji_CN.cube` 是 Resolve 导出的 **log→display 变换**，不是风格层：

- 中性灰映射 0.125→0.005、0.25→0.084、0.5→0.692/0.751、1.0→1.0（强 S 曲线）；
- 色度中位数 `k = 1.33 / 1.22`（**放大**而非压缩），色相旋转四分位 ±88°（无统一方向）。

所以它们不能直接套用；单矩阵拟合平均色度误差 0.48（`tools/cc_fit.py`），
只能取「去饱和方向」。真正复刻需要 gamma 层（cpapp 初始化数据），属改固件，
A7C2 就是往 cpapp 写 3,872 字节曲线记录才做到的。

### 7.6 B 版（block13）探针设计

1. 只改 **一个 bank、一个端点、一个槽** 的 6 个 int16（其余保持工厂值），
   确认画面有可归因的变化；
2. 若无效 → 该层在此固件未启用，B 版放弃，改走 gamma 层路线（需碰 cpapp，属改固件）；
3. 若有效 → 用 16 槽做按色相分区的降饱和，得到 CC/NC 的辨识度。

## 8. 第三次路线修正（CC1 的真实语义与两次失败）

### 8.1 权威换算：v ↔ r（R5 研究文档）

CC1 每槽 64 B，有效 24 个 int16（3 组各 8 个，对应 7842/7844/7845）。机内 8 值 v 与「RAW 表达」r 的换算是可逆的（refs/other/r5reset/fl23-colour.md 705 行起）：

    r = [v3, v0, v1, v2, 2*v7, 2*v4, 2*v5, 2*v6]
    v = [r1, r2, r3, r0, r5/2, r6/2, r7/2, r4/2]

实测可精确往返（工厂 PT 记录往返一致）。

### 8.2 失败一：把 r 当 3×3 矩阵做行和归一（CC 仍蓝、ST/VV 变黑白）

按 block13 的公式 M = [[d0+d4+1024, -d0, -d1], [-d2, d2+d5+1024, -d3], [-d6, -d7, d6+d7+1024]]（d = r - [0,0,0,0,1024,1024,1024,1024]）把 CC1 也当矩阵，做了「向亮度矩阵插值 + 行和≈1024」的去饱和，真机结果仍是蓝色溢出/闪烁，说明该公式对 CC1 不成立（文档里它只用于 block13）。

同一次写入还暴露一个工程事故：写入基线取了 unit-02a40001.factory.bin（其中 slot0 / slot2 恰好是早前实验留下的全 0），整块 8192 B 覆盖后 ST、VV、1ST 变黑白。→ 规则：任何整单元写入都必须以「当前实时单元」为基线，绝不能用历史快照。已用写前备份 .orig 全线回滚。

### 8.3 观察到的硬事实（用于推翻旧假设）

| 写入 | 结果 |
| --- | --- |
| 全 0 记录（8 值全 0） | 该外观变黑白（亮度保留、色度消失） |
| 工厂记录（v6 恒 563，v4/v5/v7 随外观变） | 正常 |
| 工厂值 ×0.6（v6 保持 563） | 去饱和但蓝色命中溢出并闪烁 |
| 矩阵插值（行和≈1024） | 同上，无改善 |

v6 在全部 10 个基础外观里恒为 563（SE 是 558），是固定基座而不是外观系数；只缩 v4/v5/v7 而不动 v6，等于单独抬高蓝通道，这最能解释「蓝色溢出」。

### 8.4 R5 文档的旁证：CC1 是「按色相选择性」的彩度层

文档 1017 行记录了一次受控实验：把 ST 的十个颜色字段换成另一机型的 ST 数据后，「主要变化为暖色、红黄色的彩度减弱，灰背景基本保留；不是整张图一致偏冷」。→ CC1 不能整体去饱和，它按色相选择性生效。用它做「经典正片」整体褪色不成立，这也解释了为什么无论怎么缩放都拿不到 CC 的观感，只会把某些色相推到出格。

### 8.5 结论与后续可选路线

1. CC1（运行时、零风险）：最多做温和的按色相彩度调整，只能给出细微差别，做不出 CC/NC；
2. block13（运行时）：此固件实测整块清零画面无变化 → 该层未启用，放弃；
3. gamma 曲线（cpapp 初始化数据，改固件）：A7C2 的正解，需要写 /cp/cpapp-b.bin。写入能力已具备（src/a6700win/flash.py，含截断/追加、回读校验、断电实测持久），缺的是 A6700 侧的曲线记录偏移与格式，需要继续静态定位；
4. 现状保留：菜单名 CC/NC（UXC 已改）+ CC1 温和降饱和，作为「可用但不等价」的成品。
