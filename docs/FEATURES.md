# 现有功能说明

这份文件按 [README](../README.md) 顶部「功能状态」表逐项展开：**只写已经做出来、能点、能跑的东西**，
每条都注明入口、它到底做了什么、真机验证到哪一步、以及已知边界。待办项与可行性结论见
[PROGRESS.md](PROGRESS.md)、[ROADMAP.md](ROADMAP.md)。

一句话概括：**把机身里被隐藏的四项功能解锁／关回去，改相机菜单里的外观颜色与名字，全部走只读预检 +
写入后独立回读，能备份能还原。**

---

## 一、机身功能（写入固件字段）

### 1.1 只读兼容性预检

| | |
| --- | --- |
| 入口 | 程序第 3 步「相机准备」→ 勾选四项确认 → **开始只读检查** |
| 读什么 | 固定窗口 **260 个扇区 / 133,120 字节**（功能字段所在的目录区） |
| 怎么判 | 逐字节比对已知字段、结构守卫与未管理区哈希；任何未知偏差整次中止 |
| 输出 | 兼容性（通过／不通过）+ 六个功能项各自的开关状态 |
| 真机 | 2026-10-23 通过；2026-10-25 复跑：260 扇区、`write_attempted=False` |

**它不写相机。** 程序里没有「强制写入」开关，这一步报不兼容就应停下，把日志贴到 Issue。

### 1.2 解锁 / 关闭四项机身功能

| 功能 | 解锁后机身里的变化 | 真机验证 |
| --- | --- | --- |
| **电子快门声音** | 菜单多出 4 项：电子快门带「克哒」声，「除快门以外」与「关」是静音，重启后保持 | 实机回放确认 |
| **关机快门帘** | 正常关机时快门帘闭合护住传感器，开机释放；设置保存与静音联动实测通过 | 用户实机确认 |
| **灵活曝光** | 菜单出现，视频曝光三项独立控制；关机后保存 | 实机写入 + 独立回读 |
| **原生 FTP 菜单** | 机身出现 FTP 菜单与开关，RAW+JPEG 上传实测通过 | 历史硬件验证 |

- 入口：第 4 步「功能管理」勾选 → **解锁所选功能** / **关闭所选功能**。
- 写入事务（相机侧 + 主机侧双层校验）：相机内二次校验前置内容 → 分扇区写入 → `fsync` → 回读
  → 主机独立再读一遍。
- 关闭 = 把同一批字段写回原值，菜单项随之消失；四项可以单独开关。
- 结果按状态如实报出：`completed` / `no-op` / `blocked` / `rolled-back` / `uncertain` /
  `verification-failed` / `recovery-required`。失败就是失败，不粉饰。

### 1.3 功能状态备份与整份恢复

| | |
| --- | --- |
| 入口 | 第 4 步「功能状态备份」→ **备份当前功能状态** / **恢复所选备份** |
| 备份产物 | `.a6700backup` 稀疏快照（本机实测 41,582 字节），带 SHA-256 |
| 恢复 | 整份功能字段写回 + 独立回读（本机实测 `restored`：134 扇区 / 326 字节） |
| 约束 | 同机型 + 同固件才接受；恢复与「这次勾了哪几项」无关 |

**边界：** 这是功能状态快照，不是整盘固件镜像，救不了砖。上游没有整盘备份，本项目也不发明。

## 二、连接与驱动（Windows 特有）

### 2.1 驱动准备（WinUSB 自动绑定）

1. **扫描设备**：走 SetupAPI（`SetupDiGetClassDevsW`），不需要驱动、不需要管理员，能把
   `0x0E76 Sony A6700 - Storage` 与 `0x0336 Sony A6700 - Service` 都列出来。
2. **绑定 WinUSB**：用随包附带的 libwdi（`wdi-simple.exe`，离线可用）把相机接口绑到 WinUSB；
   需要管理员时自动 `ShellExecuteExW(runas)` 提权并回报进度。
3. 绑定后资源管理器里的相机盘符会消失——**正常**，此时相机只对 libusb 可见。
4. 服务模式设备（`0x0336`）在 Windows 上默认没有任何驱动（设备管理器报 Error 28），
   程序在需要时自动为它补装一次，不用手动操作。

真机：`0x0E76` → `winusb` 绑定成功（2026-10-25）。

### 2.2 服务模式救援

- 相机停在 `0x0336`（服务模式）不放时，程序自动发 `STOP_SENSER` 并等设备回落到 `0x0E76`，
  而不是要求你拔插数据线。
- 仍失败时的正确处理：**拔线 → 相机正常关机 → 取出电池约 1 分钟 → 装回开机 → 重连**。
  普通「关机再开机」不算断电重开。

### 2.3 会话冷却

两次认证会话之间默认等待 **50 秒**（`POWERFUL6700_SESSION_GAP` 可覆盖）。原因：写 CP 单元
之后紧接着再开一个会话写 145 KB 语言资源，实测第 13 次传输左右必掉线（`Pipe error`）。

## 三、外观与菜单文字

### 3.1 自定义外观颜色（CP 色度）

| | |
| --- | --- |
| 入口 | 第 5 步「自定义外观」→ **检测当前状态** → **写入配方** / **还原本页外观** |
| 改什么 | CP 色度单元 `0x02A40001`（8192 字节）里的 4 条记录：PT=bank 6、NT=bank 4、VV=bank 1、VV2=bank 14 |
| 记录格式 | 每条 64 字节 = 12 组 (Cb,Cr) int16（24 个有效值 + 8 个零） |
| 写入 | 只改这 4 条记录，其余 28 条逐字节不动；写完回读整单元比对 |
| 生效 | 改的是运行时 RAM，当场可见；**正常关机、等满 1 分钟再开机**才被相机写进 `/setting/BACKUP.BIN` |
| 拟合 | 参照 19 张 A7C2 直出对照图（72 个样本），逐色相矫正率 81.7 / 82.7 / 81.1 / 67.0% |

CLI：`python tools/looks_apply.py --confirm yes-write`（相机先切到 MSC）。

**边界：** A6700 没有可用的伽马／曲线层（cpapp 里那 9 条斜坡是死数据），所以只能改「颜色倾向」，
做不出富士的 S 形影调；理光正片／负片停在低饱和轻量版；`.cube`／`.dcp` 不能直接导入。

### 3.2 菜单文字改写（两套命名）

| | |
| --- | --- |
| 入口 | 同一页的「菜单文字」卡片：命名方案下拉 → **写入菜单文字** / **还原菜单文字** / **导入基线…** |
| 文件 | `/usr/share/app/string_simplifiedchinese_f.uxc`（ext2，145,612 字节，4,785 条记录） |
| 两套叫法 | 官方原名 `Classic Chrome` / `Classic Neg.` / `Positive Film` / `Negative Film`；中文简称 `富士CC` / `富士NC` / `理光正片` / `理光负片` |
| 改哪几条 | 每个外观有两条记录（菜单与列表各一条），四条外观共 8 个 rid，一起改以免显示不一致 |
| 写入流程 | 写入前自动存整份基线 → 整块后移 + 索引表重排 → `truncate` 到新长度 → 按 32 KB 分块写 → 整份回读比对 |
| 还原 | 有出厂基线就整份逐字节写回并校验哈希；没有基线只把文字改回出厂短名，界面会明说这一档不是逐字节还原 |

真机：英文原名写入 145,708 字节（关机重启后菜单正确显示）→ 还原 145,612 字节 / sha256
`fe263360…`（与出厂逐字节一致）→ 中文简称写入 145,692 字节并确认显示宽度正常。

CLI：`python tools/looknames_apply.py --status`（只读）；写入 `--apply --preset official|zh --confirm yes-write`；
还原 `--restore --confirm yes-write`。单条记录微调仍用 `tools/uxc_grow.py`。

## 五、数据与记录

| 路径（可用 `POWERFUL6700_DATA` 覆盖根目录） | 内容 |
| --- | --- |
| `.data/backups/` | 功能状态快照 `.a6700backup` |
| `.data/looknames/` | 菜单文字基线（整份语言资源 + `index.json` 索引：sha256 / 字节数 / 来源 / 时间） |
| `.data/run/` | 每次操作的运行记录（状态、读写扇区、时间线） |
| `.data/flash-log/` | 文件读写载荷的日志（`/usr`、`/cp`、`/setting`） |
| `.data/driver/` | 随包附带并复制出来的 libwdi 组件 |

可写目录探测顺序：`POWERFUL6700_DATA` → exe 同目录 `.data` → `%LOCALAPPDATA%` → 临时目录，
保证「提权运行」与「普通运行」看到同一个目录。

## 七、明确没有的能力

整盘／完整固件备份与恢复、位移多帧合成（Pixel Shift）、动态增强防抖（Dynamic Active）、
FL2／FL3 原生创意外观、`.cube`／DCP 直接导入、录像卡速档位修改、机器内 3D LUT。
这些上游也没实现，本项目不发明；原因与证据见 [ROADMAP.md](ROADMAP.md)、[FL2-ROUTE.md](FL2-ROUTE.md)。
