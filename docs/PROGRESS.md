## 2026-10-26 · FL2/FL3 战役（结果：做出来了，但不成立）

- **做成**：移植同机型项目 `Himpq/FireHydrant` 的两层补丁 —— B 层 `/cp/cpapp-b.bin` 33 个窗口（实写 4,456 B、1.3 秒、33/33 回读一致）+ A 层 `/usr/lib/appFw.so` 的 `0x34E5604` 112 B 转发器。冷启动后外观菜单从 **14 项变 16 项**（新增 `5VV2`、`6BW`）。
- **不成立**：A 层 override 只在基底外观是 ST 时触发，`5VV2`/`6BW` 的基底是 VV2 / BW → 它们只是别名，`5VV2` 逐像素等于 `VV2`；把 override 指到 ST 基底的槽上，一选 ST 就闪屏重启（mode 19/20 只有 movie 侧数据）。
- **因此**：「内置 10 项回索尼原厂 + CC/NC 住进独立槽」这条路走不通；四条配方仍只能写进内建记录（PT / NT / VV / VV2）。CP 色度与矩阵两单元已按出厂副本写回，与出厂 0 字节差异。
- **顺带查清**：外观菜单的显示名不是 UXC 字符串（UXC 出厂本来就是短名 `PT` / `VV`…，长名是我们自己写进去的）；appFw `0x04b597ac` 的 160 B 记录表是「外观参数页」的条目，改它不影响列表名。
- **事故**：`/cp/cpapp-b.bin` 的 `0x10D02B8`（3,872 B 音调曲线区）写成全零后 **相机黑屏无限重启**；USB 只剩 `0x0D68` / HidUsb 每 3 秒一闪，MSC 与 `0x0336` 都不出现 → 只能走 RP2040 冷启动注入。恢复素材已离线备好（`tools/fl23_recovery.py`；`.data/recovery/ramp.sparse` 4,660 B 只动 9 个扇区、`restore-b.sparse` 12,556 B 回整段出厂），等 Pico 套装到货即可救。
- 完整记录：`docs/FL23-FULL-RECORD.md`（492 行，含 §12 对话索引、§13 存疑清单）。
