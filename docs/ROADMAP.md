## 二、FL2／FL3 与第三方滤镜：调查已经做过，结论在 `docs/FL2-ROUTE.md`

这部分不是「未开始」，本项目已经做过静态反汇编 + 只读 dump + 真机 RAM 探测，结论写死在
`docs/FL2-ROUTE.md`（195 行，含确认偏移与已排除思路）。摘要：

- **颜色层可达**：CP 单元 `0x02a40001` / `0x02a4000d` 的读写在真机上跑通（`tools/cp_read.py`、
  `tools/cp_write.py`，pFunc `0x40` + `0x603/0x40` 读、`0x603/0x41` 写），改完立刻可见、掉电恢复。
  但只改色度／矩阵 ≈ 机身内的「饱和度」滑块，用户当场判定「我在相机里也能改」，产品价值不足（路线 C）。
- **真正的 FL2/FL3 要对齐 A7C2 的四层移植**：① appFw 开门（上限 9→11、追加 0x13/0x14、两个选择
  能力位、Fade 默认、槽 16/17 绑定、两个菜单产品标志）；② cpapp 扩容（数据长度 +3872 B、追加
  curve/gamma/mode 表、gamma 上界 0x2f→0x32、三处表指针改址）；③ 运行时写槽（参数 55/56、槽 23/25）；
  ④ donor 数据（`assets/fx2_fl23_donor.json`）。A6700 现状：① 转换器已定位但外观定义表／菜单门／
  槽位绑定表未定位；② 长度字段与追加空间已确认，但参数 55/56 槽、gamma 表、chroma/矩阵白名单未定位；
  ③ 已打通；④ 数据在手。
- **「菜单里出现 FL2/FL3 字样」目前无解**：A7C2 固件出厂自带这两个标签，A6700 固件里 `FL2`/`FL3`
  全 0 命中，显示文字在压缩／加密的 UI 资源里；不解开就无法新增或改名。
- **本体设置落盘位置未定位**：极端参数态 vs 默认态两轮全分区 diff，WBI(nflasha5) 与 CP(nflasha8)
  sha256 前后完全一致，其它分区只有指针表／JIT 缓存级别的变化 → 没有找到任何 look 参数记录。

下一步（`FL2-ROUTE.md` §9，已收敛为一条）：

1. ~~UI 文本可行性探针~~ **已完成，判定不可行**：外观资源 id 只有 1..11（`0x49e34d0` 的 16 字节记录表，
   紧随其后的 `0xc` 已被 `BASE_ISO_SENSITIVITY_DISPLAY_ON` 占用）；`FL2`/`FL3`、`Sepia`、`SDXC`、
   中文 UTF-8 密集串在 appFw（89 MB）+ WBI（314 MB）+ 其余 13 个分区里**全部 0 命中**
   → 显示文字在不可读写的资源包里，新增/改名菜单项不可行。
2. **CP tone 单元定位**（当前唯一低风险方向）：19 个 CP 单元已全部可读，先做「未知单元整体压扁 →
   观察对比度/层次是否变化」的判断，再按位数二分锁定。判据：不改 flash 就能让某个外观出现
   与 FL2 同向的色调差异。

若 2 也不成立，只剩路线 B（cpapp gamma 静态定位 + 新写窗口），需要新 catalog 版本与结构守卫
（现有 260 个固定扇区不覆盖 CP/appFw 的新位置），风险与周期都上一个量级。

**富士 CC / CN 等滤镜**：本质是替换 Creative Look 的**内容**（A7C2 用 LUT/DCP 编译后写入），前提是
固件存在「读取自定义 look」的代码路径。我们已有 FX2 donor 数据，但落点未定位；若固件侧不存在这条路，
就属于改固件逻辑，超出本项目「只碰已知字段、一个未知字节就中止」的安全范围，默认不做。
