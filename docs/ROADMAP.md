## 二、FL2／FL3 与第三方滤镜：调查已完成，权威结论在 `docs/FL2-ROUTE.md`

这部分不是「未开始」。本项目做过静态反汇编（`firmware/appFw-2.00.so` 89,027,992 B +
`firmware/cp/cpapp-b.bin` 17,892,024 B）、全分区只读 dump（11 个分区 + nflasha15 头部）与真机
RAM 探测（19 个 CP 单元全部读出并写入验证）。完整记录见 `docs/FL2-ROUTE.md`（252 行、10 节，
含确认偏移、已排除思路与下一步判据）。四条结论：

1. **颜色层可达但价值不足**：CP 单元 `0x02a40001`（chroma）/ `0x02a4000d`（矩阵）的读写在真机
   跑通（`tools/cp_read.py`、`cp_write.py`、`cp_patch.py`；pFunc `0x40` + `0x603/0x40` 读、
   `0x603/0x41` 写），改完立刻可见、掉电恢复。但只改色度／矩阵 ≈ 机身内的「饱和度」滑块，
   用户当场判定「我在相机里也能改」（路线 C，已验到边界）。
2. **「菜单里出现 FL2/FL3 字样」仍不可行，但功能可行**（2026-10-25 修订；2026-10-26 实测：条目已能多出两项、显示为 `5VV2` / `6BW`）：外观资源 id 只有 1..11、显示文字在不可读写的资源包里——
   这部分成立；同机型项目已用「自定义位 → CP mode 19/20」的路子做成，菜单仍显示旧名（`AI-HANDOFF.md` §18）。
3. **影调层有载体，只是我们没标定**（2026-10-25 修订）：FL2/FL3 的观感来自 cpapp 的 42 项 CP 候选模式表 + CP 单元每槽 8 项参数，
   不依赖 gamma 斜坡；「矩阵+曲线拟合残差 0.148 是模型极限」应读作「只用了色度一层时的极限」。
   本体设置落盘位置同样未定位：极端参数态 vs 默认态两轮全分区 diff，WBI(nflasha5) 与 CP(nflasha8)
   sha256 前后完全一致。
4. **可写面已从 2 个单元扩到 19 个**（§2）：若某个单元承载 tone 曲线，就能不写 flash 做出
   「像素上像 FL2」的外观 —— 这是当前唯一低风险且有产品价值的方向（路线 C′）。

下一步（`FL2-ROUTE.md` §9，当前只推一条，需要用户对着相机屏幕配合）：把 19 个单元里所有未知单元
（`0x02a40000/02/04/05/06/08/09/0b/0c/0e/0f/11`）整体压扁（数值减半），观察画面是否出现**对比度／
层次**变化（不是颜色变淡）→ 若有，按位数二分锁定单元 → 锁不住则 CP 里没有 tone 载体，只能回到
路线 B（cpapp 静态定位 + 新写窗口，需要新 catalog 版本与结构守卫，现有 260 个固定扇区不覆盖 CP/appFw
的新位置，风险与周期都上一个量级）。

路线 A（对齐 A7C2 四层移植、菜单真的多出两个外观）整体不做：没有显示文字可挂、外观定义表／菜单门
未定位、需要新写窗口。

**富士 CC / NC 等滤镜**：本质是替换 Creative Look 的**内容**（A7C2 用 LUT/DCP 编译后写入），前提是
固件存在「读取自定义 look」的代码路径。我们已有 FX2 donor 数据，但落点未定位；若固件侧不存在这条路，
就属于改固件逻辑，超出本项目「只碰已知字段、一个未知字节就中止」的安全范围，默认不做。
