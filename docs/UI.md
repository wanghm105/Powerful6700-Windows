# 界面排版规则

Powerful6700 的界面是一套「文档式」布局，不是仪表盘。改界面前先读这一页，避免再回到卡片套卡片、
一行 50 多个字、按钮贴窗口边那种状态。

## 1. 基本骨架

```
侧栏 228px │ 内容区（可滚动）
           │   页头：步骤条 / 标题 / 副标题 / 发丝线
           │   内容列（上限 800px，随窗口收窄时收窄）
           │ 页脚条：上一步 …… 提示 下一步
           │ 状态栏 38px
```

- 内容列宽度由 `src/a6700win/gui/pages.py` 的 `COLUMN_WIDTH = 800` 决定，桌面 1180px 宽时两侧各留
  76px。列宽在 `_fit_gutters()` / `_fit_column()` 里跟随窗口尺寸更新。
- 内容列的左边距**由窗口宽度算出**（不是由滚动视图宽度算出）。滚动条出现或消失时列不能左右跳，
  否则换页会看到内容横向抖动。
- 页脚控件与内容列左/右对齐：`_fit_gutters()` 把同样的边距写给 `footer_bar` 和 `shell`。

## 2. 间距刻度

只用 `4 / 6 / 9 / 12 / 16 / 18 / 26 / 30` 这几档：

- 页面 `root` 外边距 30/26/30/26，块之间 18；
- 卡片内边距 18，卡片内元素之间 12，标签与值之间 10；
- 段落内部 5–6。

## 3. 页头

步骤条 `StepChip`（第 N 步 · 共 6 步）→ 标题 `Title` → 副标题 `Subtitle` → `Divider` 发丝线。
标题只有一个，副标题写一句话说明这一页做什么，不重复卡片里的正文。

## 4. 内容组件

| 场景 | 组件 | 规则 |
| --- | --- | --- |
| 分组内容 | `Card(title)` | 一种边框即可，**不要**在卡片里再放带边框的块 |
| 条目说明（须知） | `SectionRow(index, section)` | 01…05 编号 + 标题 + 右缘 Badge + 正文，段落间距 18 |
| 键值说明 | `QGridLayout` + `Faint` 标签列 | 标签列固定宽度（76 或 150），正文 `WrapLabel(Muted)` |
| 结论 | `objectName="Verdict"` | 绿色 callout，一段话说清「能/不能」 |
| 状态标记 | `Pill` / `Badge` | 只放在标题行右端，不单独占一行 |
| 长输出 | `LogBox` | 高度 192 起，等宽字体 |

正文行宽上限约 700px（中文约 40–45 字）。超过这个宽度的段落必须改用键值列表或拆段。

## 5. 按钮

- 一行里的顺序就是操作顺序，从左到右；破坏性/次要动作在左（Ghost），主操作在最右（Primary）。
- 行内先 `addStretch(1)` 再放按钮 = 右对齐；这是全站默认（关于页、驱动页、外观页、结果页一致）。
- 页脚的 `下一步` 与右侧提示文字同排，提示只写「为什么现在不能点」。

## 6. 已验证的坑

- 只给内容列设 `maximumWidth` + 两侧 `addStretch(1)`，Qt 会把富余空间全给 stretch，列缩到
  `sizeHint`（实测 623px）→ 必须 `setFixedWidth` 并由 resize 驱动。
- 只在 `Page.resizeEvent` 里算列宽，切换页面后列会停在旧值 → 同时监听 `scroll.viewport()` 的 Resize。
- 用了 `QGridLayout` 忘记 import，单元测试看不出（stub 数据不渲染那个组件），真机才 `NameError`。
