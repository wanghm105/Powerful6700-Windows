## 二、逐项详版（每项的入口、落到哪、验到哪、边界）

### ★ 可无损还原，具体是哪三条

| 写进去的东西 | 还原手段 | 实测证据 |
| --- | --- | --- |
| 四项机身功能的固件字段 | 把同一批字段写回原值，菜单项随之消失；四项可单独开关 | 真机开／关双向写入通过 |
| CP 色度单元 `0x02A40001` 里的 4 条记录 | 「还原本页外观」写回出厂记录；整单元回读比对 | 回读差异 0 字节 |
| 语言资源 `/usr/share/app/string_simplifiedchinese_f.uxc` | 写入前自动存整份基线，还原时整份逐字节写回并校验哈希 | 145,708 → 145,612 B，sha256 `fe263360…` 与出厂一致 |

没基线时的降级路径会明说：只能把文字改回出厂短名，文件字节与出厂不同，界面照旧标注这一档不是逐字节还原。

### ① 四个滤镜 + 两套菜单文字

- **槽位与落点**：PT = bank 6、NT = bank 4、VV = bank 1、VV2 = bank 14；每条记录 64 字节 = 12 组 (Cb,Cr) int16（24 个有效值 + 8 个零）。四个外观各 12 个色相档，共 48 个色相单元。
- **只改这 4 条**：单元内其余 28 条逐字节不动，写完回读整单元。
- **拟合口径**：参照 19 张 A7C2 官方直出对照图（切出 72 个样本），真机累计 10 轮 × 9 帧 ≈ 90 帧。
- **矫正率**：CC 81.7%（RMS 0.183）／NC 82.7%（RMS 0.173）／PF 81.1%（RMS 0.189）／NF 67.0%（RMS 0.330）。
- **生效方式**：改的是运行时 RAM，当场可见；要跨关机保留，正常关机、等满 1 分钟再开机，让相机自己写进 `/setting/BACKUP.BIN`。
- **菜单文字**：`string_simplifiedchinese_f.uxc`（145,612 B / 4,785 条）。每个外观有两条记录（菜单与列表各一条），四个外观共 8 个 rid 一起改，避免出现「有的地方变了有的没变」。
  - 官方原名：`Classic Chrome` / `Classic Neg.` / `Positive Film` / `Negative Film`（写入后 145,708 B，关机重启后菜单显示正确）
  - 中文简称：`富士CC` / `富士NC` / `理光正片` / `理光负片`（145,692 B，显示宽度正常）
- **两套命名可随时切换，不用重连相机**；实际写进去的是哪一版，由文件内容判定，状态列会写「已是目标文字 / 出厂短名 / 两条记录不一致」。

### ② 电子快门声音

菜单多出 4 项：电子快门带「克哒」声，「除快门以外」与「关」是静音；重启后保持。实机回放确认。

### ③ 原生 FTP 菜单

机身出现 FTP 菜单与开关，RAW+JPEG 双传通过（历史硬件验证）。

### ④ 关机快门帘

正常关机时快门帘闭合护住传感器，开机释放；设置保存与静音联动实测通过。

### ⑤ 灵活曝光

菜单出现，视频曝光三项独立控制；关机后保存。真机写入 + 独立回读。

### ⑥ 功能状态备份与整份恢复

- 产物：`.a6700backup` 稀疏快照（本机实测 41,582 字节），带 SHA-256。
- 恢复：整份功能字段写回 + 独立回读，实测 `restored` 134 扇区 / 326 字节。
- 约束：同机型 + 同固件才接受；恢复与「这次勾了哪几项」无关。
- **边界**：这是功能状态快照，不是整盘固件镜像，救不了砖。

### ⑦ 只读兼容性预检

- 读固定窗口 **260 扇区 / 133,120 字节**（功能字段所在的目录区），逐字节比对已知字段、结构守卫与未管理区哈希；任何未知偏差整次中止。
- 输出兼容性结论 + 六个功能项各自的开关状态。
- 真机：2026-10-23 通过；2026-10-25 复跑 260 扇区、`write_attempted=False`。
- 这一步不写相机；报不兼容就该停下，把日志贴到 Issue。

### ⑧ 驱动准备（WinUSB 自动绑定）

- 用 SetupAPI（`SetupDiGetClassDevsW`）扫描，不需要驱动也不需要管理员，能同时列出 `0x0E76 Sony A6700 - Storage` 与 `0x0336 Sony A6700 - Service`。
- 用随包附带的 libwdi（`wdi-simple.exe`，离线可用）把相机接口绑到 WinUSB；需要管理员时自动 `ShellExecuteExW(runas)` 提权并回报进度。
- 绑定后资源管理器里的相机盘符消失，属正常——此时相机只对 libusb 可见。
- 服务模式设备在 Windows 上默认没有任何驱动（设备管理器 Error 28），程序按需自动补装一次。

### ⑨ 服务模式自救与会话冷却

- 相机停在 `0x0336` 不放时，自动发 `STOP_SENSER` 并等设备回落到 `0x0E76`，不用拔插数据线。
- 仍失败时的正确处理：**拔线 → 正常关机 → 取出电池约 1 分钟 → 装回开机 → 重连**。普通「关机再开机」不算断电重开。
- 两次认证会话之间默认等 **50 秒**（`POWERFUL6700_SESSION_GAP` 可覆盖），界面每 10 秒报一次剩余。原因：写 CP 单元之后紧接着在同一个会话里写 145 KB 语言资源，实测第 13 次传输左右端点必掉（`Pipe error`）。

### ⑩ 一次写入：颜色 + 名字（两段会话）

- 第一段写四条色度记录（RAM），断开、等相机复位，第二段再连上写 `/usr` 语言资源。全程约 2 分钟，其中约 1 分钟是等待。
- 拆两段不是保守，是唯一能走通的做法（见 ⑨ 的掉线原因）。
- 失败处理：颜色段失败 → 整段停下、文字一个字都不动；文字段失败 → 保留已写好的颜色，并提示可以单独回滚颜色。

### ⑪ 绿色版与自检

- PyInstaller onedir 冻结包，解压双击即用，不需要装 Python。
- `--offline-self-test` 九项环境自检（Python / 平台 / 上游运行时 / 资源完整性 / 数据目录 / libusb / SetupAPI / libwdi / 控制器），`--diagnose` 出环境诊断 JSON，`--render-pages` 把七页界面离屏渲染一遍。
- 适配方式是启动时注入 30 个替换点，不改上游运行时源码，上游发版时可整目录替换后重新对齐。
- 数据目录探测顺序：`POWERFUL6700_DATA` → exe 同目录 `.data` → `%LOCALAPPDATA%` → 临时目录，保证提权与不提权看到同一个目录。
- 测试：`pytest tests -q` → 93 passed / 1 skipped。

- 离线把 CC 的口径从 RMS 0.194 压到 **0.164**（矫正率 80.6% → 83.6%），配方是 `pair2 × 0.60、pair6 × 0`。

- CC 的缺口集中在蓝端：330–360° 蓝档 0.97 对目标 0.53（差 0.44）；把蓝端四档摘掉重算，RMS 是 0.137。也就是说 0.183 里有大半是这个缺口。

## 四、❌ 不做的，理由

| 项 | 为什么不做 |
| --- | --- |
| 整盘固件备份 | 上游没有这个能力，本项目不发明；现有的是功能状态快照，救不了砖 |
| FL2 / FL3 原生创意外观 | **2026-10-25 更新：功能侧已被同机型项目（`Himpq/FireHydrant`）在 2.00 上真机打通**（自定义位 → CP mode 19/20 + cpapp 33 窗 + CP 空槽参数），本项目尚未移植、列进下一阶段；新增菜单文字仍不可得，只能沿用旧名。原判断「纯改颜色层 ≈ 饱和度滑块」只适用于色度一层，不含影调/参数层 |
| 机内 3D LUT | CP 只有 12 对 (Cb,Cr) + 增量表，只改色度一层时残差 0.148 已是该层极限（影调层尚未标定）；富士官方 19 个 LUT 全是 `F-Log / F-Gamut → ETERNA / WDR` 的录制域转换，A6700 只有 S-Log3 / HLG，输入域接不上 |
| `.cube` / `.dcp` 直接导入 | Resolve 导出的灰阶被烤成 S 曲线（0.25→0.083、0.5→0.690），四种域解释与相机 CC 差 RMS 0.53–1.19，不能当「CC 应该是什么颜色」 |
| 录像卡速档位（V60 探索 / 4K120） | 速率等级模型真实存在（c10／u3_v30／v60／v90／cfe200／cfe400），但判定分支没定位到，判定在 `.text`，当前 260 扇区写窗口不含；目前没有可以安全下手的 4 字节补丁 |
| 像素位移多帧合成 | 上游真机稳定性失败，已撤回 |
| 动态增强防抖 | 上游实验未完成，应用内禁用 |

## 五、数字口径（别把矫正率读成相似度）

- **矫正率不是逐像素相似度。** 81.7% 不等于「81.7% 的像素一样」，也不等于「观感相似度 81.7%」。人眼对暖区中段差异最敏感、对深蓝最不敏感，CC 那 0.44 的蓝端缺口在画面上比数字看着更不显眼，但它确实存在。
- **影调层尚未标定（2026-10-25 修订）。** cpapp 里那 9 条 1024 B 斜坡确实是死数据（改成 gamma 2.2 后实拍与屏幕都无变化），但影调靠「42 项 CP 模式表 + 每槽 8 项参数」表达（同机型项目已据此做出 FL2/FL3）；下面的数字只代表**色度一层**的拟合。
- **NC 的窄带品红缺口（0.34）是逼近出来的**，靠 pair2 的宽下压到 RMS 0.173；真正的窄带需要逐色相权威，`0x02A4000D` 做不到。
- **PF / NF 停在低饱和轻量版**，不是官方观感复刻。

## 六、使用前提（发布时一起给）

1. 只适配 **A6700 固件 2.00**。A7C II、A7CR、A7 IV、A7R V、ZV-E10 等机型不能用，这个项目也兜不住。
2. 每次写入前先跑只读检查；报不兼容就停，没有强制写入的开关。
3. 写入中途掉线后不要直接重试：拔线 → 关机 → 取电池约 1 分钟 → 装回开机 → 重连 MSC。
4. 颜色改完想持久，正常关机并等满 1 分钟再开机。
5. 一个会话里不要既写 CP 单元又写 145 KB 语言资源，用「一次写入」那张卡片，它替你拆好两段。
